# Personal UI packages

These packages support JG apps and are deliberately excluded from the public website catalog. The private gallery is a development tool and never ships in npm tarballs.

| Package                | Ownership                                                                                                                                                                                                                                                                                                                                 |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `jg-personal-ui`       | Shared JG palette, Ubuntu Sans fonts, radius, semantic tokens, token-name exports, and canonical mark/favicon artwork. No React or Astro dependency.                                                                                                                                                                                      |
| `jg-react-ui`          | Consumer-themed React implementations, Button, Badge, IconTile, Alert, controls/forms, menus/tabs/tooltips, plain text/tables, dialogs/drawers/layout, routing/query recovery, file uploads/audio input, Markdown/code/media/editors/diffs, preference/theme providers, scoped error feedback, notifications, `cn`, and shared contracts. |
| `jg-personal-react-ui` | Direct re-exports of the generic components plus JG styling, the decorative JgMark, and the optional system-theme fallback.                                                                                                                                                                                                               |
| `jg-personal-astro-ui` | Existing Astro components. Its current styles remain independent until the planned foundation migration.                                                                                                                                                                                                                                  |

The React implementation originates at Moldea commit `2920a7b0a6e814e95872fcdd6dd8746ae422c038`. Button retains its variants, sizes, badges, native props, refs, and `asChild` API. Touch sizes preserve 44px targets under a coarse pointer, including at tablet widths. Badge, IconTile, Alert and its title/description/action slots retain the pinned public props, variants, defaults, and slot behavior. The internal slotted-render hook uses named React imports for ESM compatibility, and unnecessary prop casts are removed to satisfy this repository’s TypeScript lint rules. JG styling maps the generic token contract to the shared palette, including a visible dark-theme link color. Moldea and HQ are unchanged.

## Styles

A React application imports Tailwind once, then `jg-personal-react-ui/styles.css`. Optionally import `jg-personal-react-ui/system-theme-fallback.css` afterward to apply dark utility variants before a theme provider runs. Explicit `.light` and `.dark` classes take precedence over the system preference. No theme provider or persistence side effect runs on import.

Consumers of the generic package supply the CSS custom properties described in its README, then import `jg-react-ui/styles.css`. The generic package supplies no brand palette. Stylesheets are explicit exports and marked as side effects so bundlers retain them.

Preference normalization preserves valid fields individually, including an explicit `null` dismissal timestamp when overriding a previously dismissed install prompt. This corrects the source helper’s null-as-default merge behavior while retaining the nullable preference contract. In-memory stores are created per provider; equivalent snapshots retain identity and do not notify subscribers.

## Preferences and document theme

Preference stores are provider-local. The optional captured `storageId` uses jg-storage’s ASCII letter/digit/underscore/hyphen rules and defaults to `jg-ui-preferences`; `getUiPreferencesStorageKey` owns the raw key contract. A keyed remount switches namespaces. Local providers follow matching storage events, read-only providers deny changes, and remote providers serialize/coalesce optimistic updates and roll back rejected batches to current authoritative props. Applications own remote adapters and cache updates. Unmounted providers have no late persistence or feedback effects.

Render `ThemeInitializationScript` in the document head with the provider’s matching namespace and optional CSP nonce. Initial render snapshots use props/defaults without browser I/O, then synchronize storage after hydration. ThemeProvider applies the document root class, and ThemeToggleButton uses the source capability/pending behavior. Use one document theme owner and one Toastr host; their effects are document-wide even with multiple isolated preference roots. Toastr preserves source icons, slots, props, stacking, and notification APIs, with JG roles supplied by the personal adapter, coarse-pointer targets, reduced motion, and a hydration-safe body portal.

The pinned preference/theme/toastr source paths were re-inspected before this port and had no live drift. Adaptations retain the source APIs while replacing the global store and private error registry, keeping current resolver/adapter refs after commits, preserving cancellation privacy, validating namespaces, and correcting explicit-null normalization. Theme root effects rely on React’s browser effect lifecycle; server rendering performs no root mutation. Toastr uses the configured font role. JG stylesheet overrides keep default-button and toast-action hover text readable against the retained translucent dark surfaces.

## Controls and source fidelity

The controls/text port rechecked all twelve component directories plus native-button/final-focus helpers against the pinned source; those paths had no live drift. Form, menu, tabs, tooltip, link, copy, divider, empty-state, progress, spinner, and plain typography retain source props and behavior. Code typography and Markdown now have real implementations. Source regression scenarios are carried into real-browser tests; semantic composition and malformed-slot guards also have server-side tests.

Intentional adaptations use named React imports, React 19 context syntax, strict optional internal dismiss-handler types, scoped copy error feedback with latest committed resolver refs, explicit component border roles in place of Moldea's global document reset, and package-owned animation imports. Menu popups scroll within Base UI’s available viewport dimensions, and long labels wrap, so 44px touch rows do not clip commands in a reduced-height viewport. Touch fields use 16px text and 44px heights; tabs preserve compact fine-pointer geometry while retaining coarse-pointer sizes. Reduced-motion styles cover transitions and source animation, including state-specific animation overrides on select/menu popups so `data-open` utilities cannot override them, and the switch thumb transition. Tooltips follow Base UI’s supplementary visual-label contract: the trigger must have an accessible name, and essential help stays inline or in a popover; no tooltip ARIA role is synthesized. See https://base-ui.com/react/components/tooltip. JG binds inverse control roles and flat field shadows without duplicating components. Button link/hover overrides use the retained `group/button` marker, so menu and tooltip trigger slot attributes cannot bypass the JG colors; a dark default-menu-trigger hover regression is covered. CopyButton retains its native millisecond timer contract; `jg-react/useCopyFeedback` uses positive finite seconds and a different invalid-duration contract, so it is not substituted here. The unused private progress-transform helper is omitted. Menu item contracts omit the inherited React text-selection `onSelect` before applying the source cancelable command event type, resolving an incompatible intersection. An uncontrolled checkbox initialized with `defaultChecked="indeterminate"` clears its mixed state after activation; controlled `checked`/`indeterminate` props remain authoritative. This corrects the pinned wrapper’s permanently mixed default and is covered by a reproduced failing regression. Keyboard menu activation also distinguishes Base UI’s native scrolling prevention from consumer cancellation: command callbacks run for Enter/Space, explicit click/select vetoes still work, and only dismiss reasons inspect the native event when closing. A consumer click veto also stops Base UI’s later item handler when no `onSelect` alias is supplied. Both keyboard failures were reproduced before the local correction.

The private gallery composes real validation/errors, choice label rows, select options, menu veto/submenu commands, tab overflow, copy feedback, long inline text, and labelled keyboard-scrollable tables. The installed identity probe compares every generic runtime export with its personal re-export. Tabs ref attachment uses React 19’s returned cleanup contract; the redundant null-detachment guard is removed while object refs, callback refs, and callback cleanup remain tested. See https://react.dev/reference/react-dom/components/common#ref-callback. The package Vite test configuration prebundles the used Base UI entries to prevent dependency-reload races during browser collection.

## Dialog and navigation ownership

The pinned modal and layout implementations retain their public compound APIs, controlled callbacks, native slots/refs, fixed headers/actions, one scrolling body, generated mobile Back controls, and focus return. Generic and personal navigation entries directly re-export jg-react-router; no second registry or provider context is created. Drawers retain explicit application-owned route dismissal. The source does not add dialog history entries; host applications own history and route destinations.

ConfirmationDialog retains the source's one-document imperative Zustand store. It resets before calling completion, supports reentrant replacement sessions, and leaves application callback errors with the caller. Do not mutate that store during server rendering. Other dialogs retain their latest controlled content until close completion; mobile snapshots ignore late captures after reopen/unmount and fall back to normal dismissal when unavailable.

The source DialogContent asChild validation now resolves the panel once before checking its direct regions. This makes its existing invalid-element guard reachable rather than hiding it behind the region error. Native misuse errors are documented on the public component boundaries. Other adaptations are named React imports, React 19 context syntax, exact optional internal props, explicit border tokens in place of a global document reset, generic surface-shadow/page-gutter roles, and JG bindings. The drawer gutter helper also retains an existing inline custom-property priority during replacement, fixing a reproduced WebKit failure before restoring the original value/priority. Compact modal close buttons also have actual 44px coarse-pointer boxes because the pinned pseudo-element hit area failed real Firefox touch targeting. Source tests run in real browsers here; desktop focus scenarios select a desktop viewport and close assertions wait for native completion.

The private gallery puts forms inside dialog bodies with associated fixed submit actions, keeping valid dialog-role semantics without changing the source asChild API. It adds compact/page dialogs, nested alerts, busy dismissal, destructive decisions, a scrollable drawer, and a separate semantic layout route. Its authored page styles are scoped so they do not alter portalled headers or footers. Installed consumers verify router provider/hook identity and install the gallery's exact React Router version.

## Application error feedback

`ErrorFeedbackProvider` and `useErrorFeedbackResolver` share one scoped policy across generic and personal imports. Applications supply `jg-exception`'s `createErrorFeedback` result with their authored code messages and access-loss classification. Unconfigured trees use generic copy without raw diagnostic text or unknown codes. Cancellation is preserved, and a resolver that throws falls back to the generic policy. No mutable global application policy is installed.

## Private React gallery

```bash
pnpm turbo run build --filter=jg-personal-react-ui
pnpm --filter jg-personal-react-ui gallery:dev
pnpm --filter jg-personal-react-ui test:e2e
```

The gallery uses published package exports, including the head initialization script, persisted settings, theme controls, and real notifications. `?theme=light` and `?theme=dark` exercise explicit preferences; an absent preference follows the OS. The Playwright suite checks 320px, tablet, and desktop layouts in both schemes, keyboard activation and visible focus, disabled controls, reduced motion, axe, and coarse pointer target sizes. Its preview process owns and stops its Vite child.

Release verification copies this gallery into a temporary consumer and installs the exact UI and sibling tarballs. It builds with Vite and Tailwind, checks component and React identity, and runs the same Chromium, Firefox, and WebKit scenarios. It reuses the release fixture's bounded command lifecycle and teardown. Fonts are resolved from the foundation's runtime dependencies. Gallery code and tests are excluded from the packages' production builds and tarballs.

The foundation owns `src/brand/constants.ts` and generated standalone `src/assets/jg-mark.svg` and `jg-favicon.svg`. `JgMark` renders those constants directly. `brand:generate` updates the raw SVGs atomically; `brand:check` runs during builds and rejects drift. Tests compare generated output with the unchanged Astro artwork until migration. The generator is development-only and its filesystem dependency never enters runtime artifacts.

Until Astro adopts the foundation, the foundation's token test checks that its declarations still match Astro's source values. Page geometry, component composition, and inverse-section behavior remain owned by Astro.

## Query and route surfaces

The React layers expose the same `RouterRoot`, route-progress, global-recovery, query-boundary, query-loader, pagination, alert, and retry-toast implementations. `jg-react-ui` depends on the existing `jg-tanstack-query` and `jg-sw` primitives. Query clients and application error policy stay consumer-owned. The query boundary reuses the shared initial-resolution hook, including its access-loss latch, while the nearest scoped resolver supplies copy and classification. No private Moldea code map is copied.

The private `/queries` gallery uses actual TanStack queries against a fixed four-page text fixture. Browser scenarios replace only HTTP responses and verify initial loading, retained data, revoked access, failed retries, successful recovery, real toasts, and route transitions. Its data-router host composes `RouterRoot` and `PageOutlet`; global recovery is available at `/route-error`. The fixture's application-owned `GALLERY_ACCESS_REVOKED` and `GALLERY_UNAVAILABLE` exceptions share the stable diagnostic message `Private gallery response diagnostics`; they are not UI package error contracts. The access-revoked code alone triggers the gallery's scoped access-loss policy. Requests have a ten-second deadline and respect query/navigation cancellation.

Intentional source adaptations in this slice include the shared query-state hook, scoped error resolution, committed toast query/policy refs, deferred publication for later-mounted hosts, labelled route-error focus recovery with native refs, synchronous guards against overlapping retries/refreshes, settled synchronous retry failures, actual coarse-pointer recovery targets, and safe-area positioning for route progress. Standalone gallery pages supply their own safe-area padding. JG binds global recovery to the existing inverse palette and generic selection/color-scheme roles. The source commit remains `2920a7b0a6e814e95872fcdd6dd8746ae422c038`; the seven component directories had no live drift when this slice was extracted.

## Upload and recording ownership

FileUpload, FileUploadDialog, ImageUploadField, and AudioInput retain the APIs from the same Moldea source commit. The nineteen production source files were extracted from that commit; their live production directories had no drift at extraction. Public personal entries directly re-export the generic implementations and contracts. Upload state reuses jg-react's existing queue; react-hook-form and its Zod resolver retain the source transcription form behavior.

Intentional adaptations include scoped error feedback, named React imports, strict internal optional props, committed dialog callback refs, actual 44px coarse-pointer targets, wrapping action labels, and static waveform/spinners under reduced motion. Reproduced regressions led to session guards for late permission/transcription/delivery results, cleanup of partially initialized Web Audio, a preview fallback keyed by image URL, and one status notification per transition under Strict Mode. External starts wait for the portalled recorder to mount; active reset immediately releases resources and returns to idle. The optional public result callback remains optional, so the unreachable internal missing-handler error is omitted. Cancellation remains silent while diagnostic callbacks stay available. JG maps the uploaded-status icon to its readable primary role in both themes. Owned audio callback errors are documented in the generic package's errors reference; caller-coded failures preserve their diagnostics while the nearest resolver supplies visible copy.

The private /inputs gallery composes native file selection, bounded queues, automatic/manual finalization, current-image replacement/removal, microphone permission recovery, transcription editing, and send retry. Its caller-owned adapters use fixed local fixture requests with a ten-second deadline and owner cancellation. They never upload the selected files or microphone bytes. The gallery-only GALLERY_INPUT_UNAVAILABLE exception has the stable message Private gallery input diagnostics. It is separate from the package's public error contracts. Browser tests replace HTTP responses and use jg-playwright's real MediaRecorder fake microphone; they do not qualify an external provider or a physical phone keyboard. Linux WebKit has no MediaRecorder; its gallery journey verifies the unsupported-browser recovery UI, while Chromium and Firefox exercise real encoding.

## Markdown and code ownership

The Markdown/code/media port uses the same pinned Moldea commit. Reinspection found no live drift in its eight component/shared directories or InlineCode. Source names, props, defaults, renderer overrides, variable tokens, image width hints, source metadata, copy/wrap controls, and simple fenced-diff semantics are retained. The complete CodeDiff viewer is also available through its dedicated entry. Markdown-variable helpers remain internal, shared with the editor. Intentional adaptations use scoped preference stores, React 19 context syntax, explicit Node grammar/style filenames with private declaration aliases, cached syntax maps, and unchanged-input Markdown parser memoization. YouTube URL policy reuses jg-utilities while retaining the source's narrower routes; runtime-invalid branded IDs expose its canonical error contract. JG syntax maps to the existing foundation tokens; there is no second JG color palette. Generic consumers retain unbranded syntax fallbacks.

The phone regression is covered in the private `/markdown` gallery: overflow-hidden flex and grid ancestors contain shrinkable message columns, long unbroken prose/headings/paths/commands wrap at 320px, and tests inspect actual text bounds rather than page overflow alone. InlineCode preserves separator wbr breaks and uses overflow-wrap:anywhere. Only code and tables scroll locally; table scroll groups have keyboard focus and labels. Caller-owned Show more/collapse controls remain in the gallery composition, without adding public truncation APIs or copying HQ's backend flow. Gallery media checks intercept the external player and verify its fixed origin, permissions, title, and responsive frame; playback against YouTube itself is not qualified.

Markdown table scroll wrappers use named groups instead of landmarks, so multiple tables do not create duplicate landmark names. The expanded-message axe regression covers both tables together before collapse.

## Complete HQ base and diff viewer

The base now covers every one of the thirty component boundaries imported by HQ at the pinned Moldea commit, plus `cn`: alert, audio-input, badge, button, code-diff, confirmation-dialog, dialog, dialog-navigation, divider, dropdown-menu, empty-state, file-upload, form, global-error-boundary, icon-tile, layout, lazy-route-progress, load-more-button, markdown, markdown-editor, progress, query-boundary, query-error-alert, router-root, spinner, tabs, theme-provider, toastr, typography, and ui-preferences-provider. Necessary closure includes code preferences, query loaders, media rendering, shared contracts, and provider-local preference state. Retained HQ imports and representative file-change/message/attachment prop shapes are a compiled installed-tarball fixture in `packages/jg-react-ui/RECIPES.md`. This verifies package API usage; HQ itself is not migrated or compiled here.

CodeDiff and `patches/react-diff-viewer-continued.patch` were rechecked against the same pinned source; neither had live drift at extraction. `packages/jg-react-ui/build/diff-viewer.patch` preserves that patch verbatim. The typed build resolves pristine viewer 4.2.2 from its exact build dependency, verifies complete before/after file identities, applies every ESM hunk with zero fuzz, and bundles the viewer while preserving React single-instance ownership and the separate lazy worker chunk. Exact esbuild 0.28.0 and diff 9.0.0 are build dependencies. The upstream viewer remains a type-supplying dependency; emitted runtime imports never bypass the bundle. Generated third-party notices have an ordinary-build stale check and ship with the licenses.

Intentional adaptations use explicit grammar filenames, scoped preferences, named React imports, explicit borders/shrinking width, and 44px coarse-pointer targets. Real gallery axe failures required two checked post-patch semantic corrections: a labelled summary group instead of a nested banner, and explicit all-lines button names/expanded state because WebKit did not expose the SVG title as its name. The private style merge omits a source branch for a missing default because every call supplies an owned default. The source API, fold callbacks, styles, synchronous bounds, and large-input worker behavior remain intact. The viewer boundary is memoized: a reproduced remote-preference save repeated unchanged row tokenization before this guard. Browser tests use the actual built adapter and confirm that relevant revisions and worker state still update. The private `/diff` gallery also supplies an independent blue/system-font consumer theme to the generic entry, showing that the base does not own JG branding.

Large-diff results are cached only for the current viewer input, matching the synchronous path's single-revision ownership. A miss recomputes in the real worker; returning to an older revision does not retain its old source/result in memory. Replies for obsolete inputs cannot clear the current revision's loading state. The worker update trigger also follows controlled folding inputs, so changed `alwaysShowLines` or `extraLinesSurroundingDiff` values do not leave a large comparison blank. The checked build applies these local corrections after verifying the unchanged source patch; real-worker regressions reproduce both failures before correction. Work remains local to the viewer, with no cross-root cache or additional persistence.
